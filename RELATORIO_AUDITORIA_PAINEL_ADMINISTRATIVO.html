Relatório de Auditoria: Painel Administrativo

Projeto: Pantanal Smoke  |  Data: 16 de Outubro de 2026  |  Ambiente: Diagnóstico Estrito de Segurança (Somente Leitura)

1. Login Administrativo

Arquivo inspecionado: src/routes/admin.tsx e src/lib/store-settings.ts

  • Funcionamento atual: A rota /admin solicita e-mail e senha. A validação é feita via função loginAdmin() comparando com uma constante local. Se correto, salva uma chave de sessão no localStorage.
  • Credenciais no código: As credenciais estão escritas diretamente em src/lib/store-settings.ts (constante ADMIN_CONFIG). Como a aplicação roda no navegador, essas credenciais ficam legíveis nos scripts empacotados.
  • Validação no servidor: Inexistente no momento. A validação é 100% feita no navegador (client-side).
  • Falsificação de sessão: Crítico Qualquer usuário pode abrir o console (F12) e criar a chave no localStorage para liberar o painel visualmente.

2. Recuperação de Senha por E-mail

  • Opção "Esqueci minha senha": Não existe na tela de login administrativo.
  • Disparo de link de recuperação: Inexistente para o administrador, pois o login não está conectado ao provedor de identidade oficial do Supabase.
  • Requisitos para funcionamento: Ligar o login ao supabase.auth.signInWithPassword(), criar tela com resetPasswordForEmail() e configurar servidor SMTP personalizado no painel web do Supabase (para evitar bloqueios por taxa de envio).

3. Cadastro e Gerenciamento de Administradores

Arquivo inspecionado: drizzle/migrations/0000_pantanal_smoke_schema.sql

  • Estrutura no banco: O banco possui a tabela public.user_roles e a função has_role() preparadas para isolar administradores de clientes comuns.
  • Gerenciamento: Não existe tela visual para criar ou convidar novos administradores. A concessão precisa ser feita manualmente via comando SQL no console do Supabase.

4. Segurança e Permissões (RLS e Banco de Dados)

Tabela Leitura (SELECT) Escrita / Modificação
products Pública para ativos; Admin para todos Bloqueada para quem não tem sessão admin no Supabase
orders Próprio cliente ou Admin Atualização de status bloqueada para quem não tem JWT admin
cashback_entries Próprio cliente ou Admin Protegida contra inserção manual
store_settings Pública para o site funcionar Exige sessão autenticada de admin no banco

Chaves de API: A chave do frontend (VITE_SUPABASE_PUBLISHABLE_KEY) é pública por padrão e está correta. A chave mestre (SUPABASE_SERVICE_ROLE_KEY) está devidamente protegida no servidor.

5. Recuperação e Controle do Site

  • Recuperação do código: O código-fonte está 100% versionado no repositório GitHub (gislaynefreitas23-hue/teste1-smoke) na branch main.
  • Dependência do Supabase: Catálogo cadastrado pelo painel, fotos enviadas por upload, histórico de pedidos e cashback dos clientes residem no Supabase.
  • Backups: O plano gratuito do Supabase não possui backup automático com restauração em um clique. Recomenda-se realizar exportações periódicas ou habilitar rotina de backup.

6. Matriz de Classificação de Riscos

Classificação Situação / Vulnerabilidade Ação Recomendada
Crítico Senha administrativa fixa no código do frontend Migrar login para Supabase Auth nativo
Crítico Sessão baseada apenas em chave no localStorage Validar sessão com JWT emitido pelo servidor
Médio Sessão atual do painel não autentica com RLS Vincular o usuário na tabela user_roles
Médio Falta de recuperação de senha por e-mail no painel Implementar resetPasswordForEmail com SMTP
Baixo Ausência de rotina externa automatizada de backup Agendar exportações periódicas do banco
